# 値引きヘルパー

惣菜・弁当売場向けの値引き判断補助アプリです。
React + TypeScript + Vite で動きます。

## 起動方法（Windows 11 / PowerShell）

```powershell
npm install
npm run dev
```

表示された URL をブラウザで開きます。
通常は以下です。

```text
http://localhost:5173
```

スマホから Tailscale 等で開く場合は、PC側で以下のように起動します。

```powershell
npm run dev -- --host 0.0.0.0
```

## 確認コマンド

```powershell
npm run check:logic
npm run build
```

## エリア残数判定

通常値引の全時刻（15時 / 17時 / 18時30分 / 19時30分）で、エリア全体の商品数を入力できます。
同じエリア・同じ時刻・同じ実際の曜日の過去データを優先して比較し、足りない場合だけ暫定曜日グループ（月水 / 火木 / 金土日）にfallbackして、5段階でエリア評価を出します。

- 多い: 表示値引率 +10%
- やや多い: 表示値引率 +5%
- 普通: 補正なし
- やや少ない: 表示値引率 -5%
- 少ない: 表示値引率 -10%

過去データが3件未満の間は、従来通り手動でエリア判断します。

判定確定時は、判定元（手動 / 履歴）、比較方式、サンプル件数、採用中央値、5段階の閾値、減り方補正を `decisionBasis` として残数履歴へ保存します。

減り方比較は、追加製造やパック化を単純な売れ行きとして扱わないよう制限しています。

- 15時→17時: 追加製造が基本的にないエリアだけで使用
- 17時→18時30分: バラ商品のパック化で値引対象数が増えるため使用しない
- 18時30分→19時30分: 使用可能

## エリア残数履歴のサーバー保存

この版ではSupabase上のエリア残数履歴を判定用の正本にします。設定がない、または取得できない場合は履歴0件として手動判定へ進みます。

### 1. Supabase側の準備

SupabaseのSQL editorで `supabase_area_count_records.sql` を実行してください。既にテーブルを作成済みの場合も、判定根拠・データ形式版・アプリ版の列と5段階手動判定の制約を追加するため、更新後のSQLをもう一度実行してください。

### 2. Vercel環境変数

Vercelに以下を設定して再デプロイしてください。

```text
VITE_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=Supabaseのanon public key
```

### 3. 保存・読み込みの挙動

- 起動時にサーバーの `area_count_records` を読み込みます。端末内の旧履歴は判定へ混ぜません。
- エリア残数判定を確定して次へ進むと、画面中のstateへ反映してSupabaseへ保存します。
- Supabase未設定、または通信失敗時も画面操作は継続しますが、履歴の永続保存はされません。
- 旧URLや旧端末設定が残っていても、完成版の機能・履歴は制限されません。

## 出力データの品質情報

- 新しく保存する残数履歴・19時チェック・1日データには `dataSchemaVersion` と `appVersion` を保存します。
- 1日データの `review19Status` は、実施済み `recorded`、未実施 `not_performed`、対象外 `not_applicable` を区別します。
- 19時チェックを行わない日は「今日は19:00チェック対象外」から明示的に対象外記録を保存できます。
- 19時チェックは、チェック全体の開始・完了時刻と、各エリアの残数確定時刻を保存します。
- 19時チェックの各記録には、入力済み・対象外・未入力の件数と未入力エリアを `dataQuality` として保存します。
- 20時30分完了時の1日データにも、15時 / 17時 / 18時30分 / 19時30分 / 20時30分ごとの欠損・重複を `dataQuality` として保存します。

## 自動遷移

各値引の天候入力・値引準備開始時刻になると、完了画面以外にいても次の値引へ自動遷移します。

- 15時値引: 14:40から15時値引扱い
- 17時値引: 16:40から17時値引扱い
- 18時30分値引: 18:25から18時30分値引扱い
- 19時30分値引: 19:25から19時30分値引扱い
- 20時30分最終値引: 20:25から20時30分用の天候入力画面へ自動移行し、21時の天気・気温・風速を入力してから最終値引へ進みます。

開始ボタン自体は時刻でロックしません。15時値引などの値引率表示を確認したい場合、必要な天候入力が済んでいれば開始時刻前でも進めます。

## 完成版固定モード

習熟段階の選択は廃止し、すべての機能を常時有効にしています。設定画面に段階切替はありません。
旧 `#/step1`〜`#/step8` URLは読み込み時に通常URLへ置き換え、保存済みの旧設定値は機能判定に使用しません。

注意事項は、残り1〜2個、10個以上、定番、夜によく売れる、見た目、不人気、商品の減り方、広告商品の判断を含む9項目で固定です。
